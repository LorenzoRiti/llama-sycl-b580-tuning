Run a 35B MoE model on a single 12 GB Intel Arc B580

A small patch set and a set of measured recipes for llama.cpp's SYCL backend on Battlemage. Experts on the CPU, everything else on the GPU: 47.79 t/s decode, 638 t/s prefill at 43.5K tokens, 160K context — on a card the model does not fit into.

Why it works

The model is a sparse MoE: 35B parameters total, ~3B active per token. With --n-cpu-moe the expert FFNs stay on the CPU (read at DDR5 speed, and they are only a fraction of the work per token), while attention, Gated DeltaNet and the shared experts run at full GPU speed. That is what puts a 35B-class model, with a six-figure context, on a 12 GB card.

Second recipe: a ternary 27B at 196K

PrismML's Ternary Bonsai 2 27B (~1.75 bits/weight, 5.9 GiB) fits a 196K context on the same card with the arc-b580 SYCL fork (stock llama.cpp rejects the ternary format). Measured 53–74 t/s plain, ~49 t/s with a short thinking budget, 115 t/s on large code edits. The counter-intuitive finding: the fork's XMX weight repack is a net loss at 196K — leaving it off is 3× faster. Sweep and tables in docs/BONSAI.md.

Quick start

# apply patches on a fresh llama.cpp
git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
for p in llama-sycl-b580-tuning/patches/*.patch; do git apply -3 "$p"; done

# build (Windows + oneAPI)
cmake -B build -DGGML_SYCL=ON -DGGML_SYCL_F16=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

# run a 35B-A3B on 12 GB
set GGML_SYCL_FA_PB=160
set GGML_SYCL_HOST_PINNED_MEM=0
llama-server -m model.gguf -ngl 99 --n-cpu-moe 28 -c 163840 -fa on -ctk f16 -ctv f16
